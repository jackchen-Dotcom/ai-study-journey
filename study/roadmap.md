## 每日时间预算（按你的真实作息定制）

可用时间：**中午约 1 小时 + 每晚 8 点后**，周末更多。原则：**碎片时间做题复习，整块时间学新东西**——新知识需要连续性，别放在中午开跑。

| 时段 | 时长 | 用途 |
|---|---|---|
| 中午 | ~1h | LeetCode 1 题（写+判题+点评），或读错题本/思路库复习 |
| 晚 8 点后 | 1.5~2h | **主力时间**：按当月主线学新东西（Python地基→工程→AI项目），或刷第 2 题 |
| 周末 | 每天 3~4h | 六日节奏照旧：周六复盘日、周日测验日；剩余时间给项目攻坚 |

每周总盘：工作日 12h 左右 + 周末 6~8h ≈ **18h/周**，足够执行本路线。

**保底方案**（加班/健身晚归的崩溃日）：中午 1 题 + 睡前 10 分钟翻一眼 patterns.md。保底方案不算中断，连续性比单日时长重要——**每天 1.5h × 180 天 > 三天打鱼两天晒网的 8h**。

> 当前 9 月的具体分配：中午做题不变；晚 8 点后 = Python 地基（面向对象→异常→文件JSON→venv→git，检验标准：读懂 judge.py 每一行），预计 3~4 周完成。

### 教学策略调整（2026-09-05，基于上述盘点）

1. **概念讲解提速**：凡你已有认知底子的内容（三范式、API 调用链路、Agent 概念），不再从头细讲，直接进入手写。
2. **每个知识点强制"遮罩重写"**：我演示/你读懂 → 合上资料从零写 → 3 天后复写。与算法线的复盘方法（默写/3 天重做）完全同构——#20 默写翻车已证明"看懂≠写得出"。
3. **动手优先级 > 覆盖面**：宁可少学一个框架，多写一个能脱稿复现的脚本。

## 分阶段细节

### 阶段 0（9月）：Python 地基 —— 现在做的事继续 + 补语法

- 每日：LeetCode 1~2 题（现有队列不变）
- 每周额外 3~4 小时：Python 查漏——面向对象（你已经在写 class Solution 了）、异常处理、文件与 JSON、虚拟环境 venv、pip
- 检验标准：能不查资料写出一个多文件的小脚本；读懂 judge.py 的每一行

### 阶段 1（10月）：工程能力 + LangGraph/MCP 入门 ※ 已按 2026-09-04 搜索校准

- ※ 2026-09-05 增补（动手短板对策）：**第 2 周插入"三范式手写复现"**（半天，见 [plan-hello-agents.md](plan-hello-agents.md) 第 4 章）——用纯 requests + while 循环从零写 ReAct，把你"调用大模型看得懂、写不出"的短板直接补掉。排在 FastAPI 之前，因为它只依赖你已跑通的 API 调用能力
- **FastAPI**：写 REST 接口（/ask /judge /stats）
- **SQL**：SQLite + SQLAlchemy 增删改查 + JOIN（中小厂面试必考）
- **Git**：branch/merge 进阶，项目全部推 GitHub
- **LangGraph v1.0 入门**（第 3 周）：StateGraph → 节点/边 → 条件路由 → checkpointer。⚠️ 认准 v1 API：`add_edge(START, 'node')`（`set_entry_point` 已废弃）、`Annotated[list, add_messages]`、`create_react_agent` 已废弃改用 LangChain v1 的 `create_agent`——网上多数教程是旧版，照抄会撞 ImportError
- **MCP 入门**（第 4 周）：官方 SDK `mcp[cli]` + FastMCP，`@mcp.tool()` 注册工具，先 STDIO 跑通再接 Claude Desktop 实测
- **主项目：智能刷题助手演进**——judge.py CLI → FastAPI Web 版（+SQL 入库）→ LangGraph 编排"读题→判题→点评→归档"流水线 → MCP Server 化（让 Claude Desktop 直接查错题本）。简历叙事："CLI → Web → 图编排 → 协议标准化的完整演进"

### 阶段 2（11~12月）：Agent 与 MCP 深化（求职主武器）※ 已按 2026-09 搜索校准

- ※ 2026-09-05 增补（动手短板对策）：**11 月 LLM 应用线改为"手写驱动"**——API 调用概念你已有底子（first_call.py + 课程 1~5 章），不再从零讲 API；直接从 chatbot.py v1（9/6 开工）连续演进：多轮对话 → 异常容错 → JSON 持久化 → 收编成类。每步先自己写，卡住才看最小修正。省下的讲解时间全投给 RAG 手写（rag.py 是全新知识，第 8 章你没学过，按原计划深学）
- 11月：**LangGraph 深学**：streaming、human-in-the-loop、`create_agent` + middleware、子图/多 Agent 编排；**agentic RAG**（Agent 自主决定何时检索、多轮检索、Reflection 自检）；**Context Engineering** 实践（上下文压缩、分层记忆）
- 12月：**MCP 深化**：SSE/HTTP 远程传输、Resources、多 Server 组合；把 10 月的刷题助手升级为完整 Agent 项目；RAG 评测入门（召回率/忠实度类指标）
- **练手项目（简历主打）**：**错题本知识库问答 Agent 版**——手写 rag.py（9月末产物）+ LangGraph 编排 + MCP 工具 + agentic 检索。面试叙事："从 naive RAG 手写演进到 agentic 架构"——这比直接调框架高一个段位
- **项目深度层（2026-09-04 校准：面试官四大通病 = 功能堆砌 / 聊不出 trade-off / 场景同质化 / 验证不闭环；19 场面试 15 场追问 RAG 项目细节）**：
  - **评测闭环**：构造 20~50 条评测集，量化检索命中率 + 回答忠实度（RAGAS 思路）——简历写"有基线对比的指标"，这是与 90% 候选人的分水岭
  - **消融实验**：块大小 × top_k × 重排序的对比表格——用户硕士做过 TDMA 协议实验，实验设计是天然优势，纯转码者没有
  - **降级策略**：检索低相似度时的兜底（重试/换库/直说不知道），能讲清每种选择的代价（token/延迟/稳定性 trade-off）
  - **引用溯源**：答案带来源标注（面试验证的加分项）
- 面试八股储备：ReAct / Plan-and-Execute / Reflection 三范式、MCP vs Skill vs A2A、RAG 全链路（切块/召回/重排/评测）、幻觉缓解四层、多轮对话三大痛点（上下文混乱/状态爆炸/意图漂移）
- 算法线：medium 比例按 plan.md 阶段 B 提升
